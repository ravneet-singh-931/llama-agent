Orbit Sync API - Technical Specification, version 2.3

1. Overview

Orbit Sync is a file synchronisation service. The REST API lets customers upload, list, version and share files, and subscribe to change notifications. This document describes version 2.3 of the API. All endpoints live under https://api.orbitsync.example/v2 and accept and return JSON unless stated otherwise.

2. Authentication

The API uses OAuth 2.0 with the client credentials grant. Clients exchange their client ID and secret at the /oauth/token endpoint for a bearer access token. Access tokens are valid for 3600 seconds. Refresh tokens are not issued for this grant; request a new access token when the old one expires. Tokens must be sent in the Authorization header as "Bearer <token>".

3. Rate limits

Requests are limited per organisation. The Free plan allows 60 requests per minute, the Team plan allows 600 requests per minute, and the Enterprise plan allows 6,000 requests per minute. Short bursts of up to twice the limit are absorbed for ten seconds. Every response carries the headers X-RateLimit-Limit, X-RateLimit-Remaining and X-RateLimit-Reset. Clients that exceed the limit receive HTTP 429 and should wait for the number of seconds in the Retry-After header.

4. Errors

Errors are returned with an HTTP status code and a JSON body containing an Orbit error code, a message and a request ID. Please quote the request ID when you contact support.

OS-1001: the access token is missing or malformed.
OS-1007: the access token has expired; request a new one.
OS-2040: the rate limit for the organisation was exceeded.
OS-3302: the request payload is too large. JSON request bodies are limited to 10 MB.
OS-4410: version conflict. The file was changed by another client since the version you sent; fetch the latest version and retry.
OS-5000: internal error. These are retried safely if you send an idempotency key.

5. Idempotency

POST requests accept an Idempotency-Key header. If the same key is sent again within 24 hours, the API returns the original response instead of performing the operation twice. Keys should be random UUIDs generated by the client.

6. Pagination

List endpoints use cursor-based pagination. The default page size is 50 items and the maximum page size is 200. Each page includes a next_cursor field; pass it as the cursor query parameter to fetch the following page. An empty next_cursor means there are no more results.

7. Files and storage

Single files of up to 5 GB can be uploaded using multipart upload; smaller files can be sent in one request. Every change creates a new version, and the last 100 versions of each file are kept. Files are encrypted at rest with AES-256 and all traffic uses TLS 1.3.

8. Webhooks

Customers can register webhook endpoints to be notified when files are created, updated or deleted. Each notification is signed with an HMAC-SHA256 signature in the X-Orbit-Signature header. If an endpoint does not answer with a 2xx status, delivery is retried 5 times with exponential backoff, after 1, 2, 4, 8 and 16 minutes. After the last failed attempt the event is dropped and appears in the delivery log.

9. Regions and data residency

Customer data is stored in one of three regions chosen when the organisation is created: us-east-1 (Virginia), eu-west-1 (Ireland) and ap-south-1 (Mumbai). Data never leaves the chosen region. Request logs are retained for 90 days and then deleted.

10. Service levels and support

The Enterprise plan includes a monthly uptime commitment of 99.95%, with service credits when it is missed. Team and Free plans are provided on a best-effort basis. Official SDKs are available for Python, TypeScript and Go.

11. Pricing

The Free plan costs nothing and includes 10 GB of storage. The Team plan costs $49 per user per month and includes 1 TB of pooled storage. Enterprise pricing is agreed per contract.

12. Versioning and deprecation

Breaking changes are only made in a new major version. When a version is deprecated, customers receive at least 12 months of notice. Version 1 of the API will be switched off on 2027-01-31; customers still calling v1 endpoints should migrate before that date.
